# @lateen-os/api-gateway

API Gateway — a real, deterministic, framework-agnostic API Gateway for Lateen OS: API/Route/Endpoint/Version registries, a middleware pipeline, authentication and authorization, rate limiting and quota management, request/response validation, request context and correlation IDs, request metrics and health endpoints, service discovery, an OpenAPI/documentation model, and a Runtime Dispatcher that routes real requests through 16 sibling packages' public APIs.

Aligned with **Lateen OS Architecture v1.0 (Locked)**.

## Purpose

The API Gateway is the single, deterministic front door for every other engine in Lateen OS. It owns the API Registry (API → Version → Endpoint → Route, a four-level hierarchy with guarded lifecycles), the Middleware Pipeline (ordered, enable/disable-able steps), Authentication (an API Key Registry plus a real dependency-free HS256 JWT abstraction built on Node's `crypto`), Authorization (deterministic exact/wildcard Policy Evaluation), Rate Limiting and Quota Management (deterministic fixed-window/fixed-period counters), Request/Response Validation and Response Normalization (a minimal hand-rolled schema check, never an external validation library), Request Context and Correlation IDs, Request Metrics and Health Endpoints, Service Discovery, an OpenAPI/documentation model derived purely from the Registry, and the Runtime Dispatcher — the 12-step pipeline that actually routes a request through to one of 16 real sibling-package operations.

**No HTTP server implementation anywhere in this package.** `DispatchRequestInput`/`DispatchResult` are plain data objects; a real HTTP adapter (Express, Fastify, or otherwise — outside this package) translates an incoming request into `DispatchRequestInput` and translates `DispatchResult` back into an HTTP response.

## Stack

- Pure TypeScript, strict mode
- DDD bounded context — one module per capability, each with `types.ts` / `repository.ts` (port) / `repository.impl.ts` (real in-memory implementation), plus a `*.impl.ts` service/engine
- Framework agnostic — no Express, Fastify, NestJS, or any other HTTP framework import anywhere
- Deterministic and offline — no wall-clock timers baked in (every `create*` factory accepts an injectable `now()`), no network calls, **no LLM/AI inference anywhere in this package** — routing, auth, rate limiting, and validation are all fixed logic
- Dependency injection only — every `create*` factory takes its dependencies explicitly; see `createApiGatewayRuntime()` for the composition root
- Real, dependency-free JWT (HS256) built on Node's built-in `crypto` module — no external JWT library added
- API keys: a raw key (`lgw_...`) is generated via `crypto.randomBytes` and returned to the caller exactly once, at issuance; only a SHA-256 hash is ever persisted

## Capabilities

| Capability | Module | Notes |
| ---------- | ------ | ----- |
| API Registry, Version Registry, Endpoint Registry, Route Registry | `registry` | A four-level hierarchy (`Api → ApiVersion → Endpoint → Route`) sharing one guarded-lifecycle aggregate; `Route.targetService`/`targetOperation` are opaque strings resolved only by the Runtime Dispatcher |
| Middleware Pipeline | `middleware` | Ordered, enable/disable-able steps (`authentication`, `authorization`, `validation`, `rateLimit`, `custom`); pure `orderSteps()` sorts by sequence then id |
| Authentication Pipeline, API Key Registry, JWT abstraction | `authentication` | API key issue/revoke/verify plus a real HS256 JWT `signToken`/`verifyToken`; `authenticateRequest()` composes both into one pipeline |
| Authorization Pipeline, Policy Evaluation | `authorization` | Deterministic exact/trailing-wildcard resource+action matching; highest-`priority` matching active policy wins; default deny |
| Rate Limiting, Quota Management | `ratelimit` | Deterministic fixed-window request counters and fixed-period quotas — both reset by elapsed-time comparison, never token buckets with jitter |
| Request Validation, Response Validation, Response Normalization | `validation` | A minimal hand-rolled `FieldSchema[]` check (field/type/required) and a fixed success/error response envelope |
| Request Context, Correlation IDs | `context` | One tracked record per request, keyed by a real `crypto.randomUUID()` correlation id, moving `in_flight → completed \| rejected` |
| Request Metrics, Health Endpoints | `metrics` | Immutable per-request metric records plus deterministic health-check aggregation (`getOverallHealth()`) |
| Service Discovery | `discovery` | The registry of backend services the Runtime Dispatcher is allowed to route to |
| OpenAPI Model, API Documentation Model | `documentation` | Pure projections derived entirely from the Registry — never hand-maintained separately, never generated by a model |
| Runtime Dispatcher | `dispatcher` | The 12-step request pipeline: context open → route lookup → service availability → authentication → authorization → rate limiting → validation → invoke → normalize → context close → metrics → return |
| Relationship Layer | `relationship-management` | Integrates all 16 required sibling packages — see below |
| Query Layer | `queries` | Real, read-only `GatewayQueries` port — `findApis` / `findRoutes` / `findApiKeys` / `findPolicies` / `findRequestContexts` / `findMetrics` / `findHealthSnapshots` / `findServices` / `searchGateway` |
| Event Bus | `events` | Typed `GatewayEventMap`; every declared event is genuinely published by the service that triggers it |

## Integration with 16 sibling packages

Per the architecture rules, this package integrates with sibling packages **only through their public runtime APIs** — never a repository, never a modification to those packages, and never dynamic reflection. The Runtime Dispatcher's invoker table (`dispatcher/invoker-map.ts`) is a fixed, exhaustive lookup of `${targetService}:${targetOperation}` strings to one curated, named `RelationshipManagement` method per collaborator — the same "integrate only through explicit named public methods" discipline used everywhere else in this monorepo.

- **AI Runtime** — `getAgentContext()` fetches a real agent via `RuntimeQueries.findAgent()`. (AI Runtime has no single `createXRuntime()`; a caller constructs its own `RuntimeQueries` via `createRuntimeQueries(...)` and injects it here.)
- **Workflow Engine** — `raiseGatewayApprovalWorkflow()` defines (idempotently, per organization + request type) and starts a real gateway-approval workflow.
- **CRM Engine** — `getCustomerContext()` fetches a real customer via `customers.get()`.
- **Sales Engine** — `getOpportunityContext()` fetches a real opportunity via `opportunities.get()`.
- **Marketing Engine** — `getCampaignsContext()` reads every real campaign via `queries.findCampaigns()`.
- **Communication Hub** — `notifyGatewayEvent()` creates and sends a real `'escalation'` notification.
- **Finance Engine** — `getChartOfAccountsContext()` reads the real chart of accounts via `chartOfAccounts.list()`.
- **HR Engine** — `getEmployeeContext()` fetches a real employee via `employees.get()`.
- **Inventory Engine** — `getInventoryItemContext()` fetches a real catalog item via `catalog.get()`.
- **Project Management Engine** — `getProjectContext()` fetches a real project via `projects.get()`.
- **Customer Success Engine** — `getCustomerSuccessContext()` fetches a real record via `customers.findByCustomer()`.
- **Analytics Engine** — `recordGatewayMetric()` records a real gauge metric via `metrics.recordGauge()`.
- **Observability Engine** — `getObservabilityHealthContext()` reads every real health check via `queries.findHealth()`.
- **AI Security Engine** — `getSecurityPolicyContext()` reads every real policy via `queries.findPolicies()`.
- **AI Governance Engine** — `getGovernancePolicyContext()` reads every real policy via `queries.findPolicies()`.
- **AI Compliance Engine** — `getComplianceFrameworkContext()` reads every real framework via `queries.findFrameworks()`.

Every optional collaborator degrades to a documented no-op (`null`/`[]`) when not injected, so the API Gateway is fully usable — and fully tested — completely offline without any of them.

## Event bus

`GatewayEventMap` declares 10 events, each genuinely published by the real service that causes it:

`api.registered`, `route.registered`, `version.published`, `apikey.issued`, `apikey.revoked`, `request.received`, `request.completed`, `request.rejected`, `ratelimit.exceeded`, `quota.exceeded`.

## Usage

```typescript
import { createApiGatewayRuntime } from '@lateen-os/api-gateway';

const gateway = createApiGatewayRuntime();

const api = await gateway.registry.registerApi('org-1', { code: 'crm', name: 'CRM API' });
const version = await gateway.registry.createVersion('org-1', { apiId: api.id, version: 'v1' });
const endpoint = await gateway.registry.registerEndpoint('org-1', { apiId: api.id, versionId: version.id, name: 'Customers' });
const route = await gateway.registry.registerRoute('org-1', {
  endpointId: endpoint.id,
  method: 'GET',
  path: '/crm/customers',
  targetService: 'crm-engine',
  targetOperation: 'getCustomerContext',
  requiresAuth: false,
});

await gateway.discovery.registerService('org-1', 'crm-engine');
await gateway.authorization.createPolicy('org-1', { name: 'Allow GET', effect: 'allow', resource: route.path, action: 'GET' });

const result = await gateway.dispatcher.dispatch('org-1', { method: 'GET', path: '/crm/customers', body: { customerId: 'customer-1' } });
```

Wiring in real sibling collaborators (any subset):

```typescript
import { createCrmRuntime } from '@lateen-os/crm-engine';
import { createFinanceRuntime } from '@lateen-os/finance-engine';

const gateway = createApiGatewayRuntime({
  crm: createCrmRuntime(),
  finance: createFinanceRuntime(),
});
```

Every declared event is genuinely published — subscribe via `runtime.events`:

```typescript
gateway.events.subscribe('ratelimit.exceeded', (payload) => {
  console.log(`Rate limit exceeded for principal ${payload.principalId} on policy ${payload.policyId}`);
});
```

## Structure

```
src/
├── shared/                     # IDs, date arithmetic, primitives, errors
├── events/                     # Typed GatewayEventMap
├── registry/                   # API / Version / Endpoint / Route registries
├── middleware/                 # Middleware Pipeline
├── authentication/              # API Key Registry, JWT abstraction, Authentication Pipeline
├── authorization/               # Authorization Pipeline, Policy Evaluation
├── ratelimit/                  # Rate Limiting, Quota Management
├── validation/                 # Request/Response Validation, Response Normalization
├── context/                    # Request Context, Correlation IDs
├── metrics/                    # Request Metrics, Health Endpoints
├── discovery/                  # Service Discovery
├── documentation/               # OpenAPI Model, API Documentation Model
├── relationship-management/    # 16-collaborator Relationship Layer
├── dispatcher/                 # Runtime Dispatcher — the 12-step request pipeline
├── queries/                    # Real GatewayQueries read layer
├── runtime.ts                  # createApiGatewayRuntime() composition root
└── index.ts
```
